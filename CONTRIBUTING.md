# Contributing to drift-ui

Thanks for taking the time to help. This guide covers local setup, how a component is put together, and what a pull request needs before it can be merged.

## Setup

You need [Bun](https://bun.sh) 1.2 or newer. [Fork the repo](https://github.com/localhostd3veloper/drift-ui/fork), then clone your fork:

```bash
git clone https://github.com/<your-username>/drift-ui.git
cd drift-ui
bun install
bun run registry:build
bun dev
```

The site runs at <http://localhost:3000>. Every registry item is served from <http://localhost:3000/r/{name}.json>.

## Scripts

| Command                  | What it does                                   |
| ------------------------ | ---------------------------------------------- |
| `bun dev`                | Start the Next.js dev server                   |
| `bun run registry:build` | Rebuild `public/r/*.json` from `registry.json` |
| `bun run test`           | Build the registry, then run Vitest once       |
| `bun run test:watch`     | Run Vitest in watch mode                       |
| `bun run typecheck`      | Type-check the project with `tsc --noEmit`     |
| `bun run lint`           | Run ESLint                                     |
| `bun run format`         | Format `.ts` and `.tsx` files with Prettier    |
| `bun run build`          | Build the registry, then the production site   |

## Adding a component

1. Write the source in `registry/default/ui/<name>.tsx`. Pure logic (parsing, math, state machines) goes in `registry/default/lib/<name>.ts` so it can be tested without rendering.
2. Import helpers through `@/registry/default/...`. The docs site rewrites these paths to `@/components/ui/...` and `@/lib/...` when it shows the source to users.
3. If the component imports `radix-ui`, or passes `asChild` or `PopoverAnchor` to a shadcn primitive, write a Base UI version with the same props at `registry/base/ui/<name>.tsx`. The Base UI build at `/r/base` uses a file from `registry/base` wherever one exists and the `registry/default` file everywhere else. When the primitive is a few lines of React, such as a `role="progressbar"` div or `createPortal`, write that instead so the file stays shared.
4. Add an item to `registry.json`, in alphabetical order by name, with its npm `dependencies` and its `registryDependencies`. Depend on shadcn's built-in items by bare name (`utils`, `button`, `badge`, `input`, `label`, `popover`) so installing never overwrites a user's existing primitives. Use the `@drift-ui/` prefix only for items that exist nowhere else, such as `@drift-ui/use-controllable-state`.
5. Add `components/preview/<name>-preview.tsx`. It is the live demo and the usage example on the docs page, so keep it short and realistic.
6. Register the preview in `components/docs/preview-registry.tsx` and give it a category in `lib/catalog.ts`, in alphabetical order within that category. The `/components/<name>` page is generated from those two entries.
7. Add usage notes to `lib/agent-docs/component-usage.ts` and the prop reference to `lib/agent-docs/component-api.ts`, both in alphabetical order. They feed the docs page, `/llms.txt` and `/llms-full.txt`.
8. Add tests in `tests/ui/<name>.test.tsx`, plus `tests/lib/<name>.test.ts` if you added a lib file. `bun run test` runs `tests/ui` once against Radix and once against Base UI.

`public/r` is generated by `bun run registry:build` and gitignored, so it never goes in a pull request.

### Avoiding merge conflicts

Insert into the shared lists at your alphabetical position instead of appending, because two pull requests that add to the same spot conflict. `tests/lib/sorted-lists.test.ts` fails if a list is out of order. If two components sort next to each other and you still get a conflict, keep both entries.

### Component guidelines

- Support controlled and uncontrolled use. `use-controllable-state` handles the `value`, `defaultValue` and `onValueChange` trio.
- Spread remaining props onto the element a user expects to style, and accept `className`.
- Follow the WAI-ARIA pattern for the widget and test keyboard interaction, not only clicks.
- Read colors from the theme tokens in `app/globals.css`. Do not hard-code colors.
- If shadcn/ui already ships a component, keep its API identical.

## Code style

Prettier and ESLint settle formatting. Run `bun run format` and `bun run lint` before you push. Tailwind classes are sorted by `prettier-plugin-tailwindcss`, so do not reorder them by hand.

## Commits

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org):

```text
feat(registry): add tags input
fix(tree-view): keep focus on the collapsed branch
test(time-field): cover segment editing
```

Use the component name as the scope when the change is limited to one component. Keep one logical change per commit.

## Pull requests

1. Branch from `main` in your fork as `<type>/<issue>-<slug>`, for example `feat/14-avatar-group` or `fix/31-stepper-focus-ring`.
2. Make sure `bun run typecheck`, `bun run lint` and `bun run test` pass.
3. Open the pull request and fill in the template. Add a screenshot or a short recording for visual changes.

## Working with coding agents

[AGENTS.md](AGENTS.md) holds the issue-to-pull-request workflow for coding agents such as Claude Code, Codex, Cursor and Copilot. In Claude Code, run `/work-on-issue <number>`. Review agent output the same way you would review your own code before opening the pull request.

## Contributors hall of fame

When your pull request merges into `main`, you appear on [/contributors](https://drift-ui.dev/contributors) under your GitHub handle, ranked by merged pull requests. The page reads GitHub's contributor list, which can take a few hours to update. GitHub matches commits to accounts by email, so commit with an address linked to your account.

## Reporting bugs and requesting components

Use the [issue templates](https://github.com/localhostd3veloper/drift-ui/issues/new/choose). For a bug, include the component, the browser, and the smallest steps that reproduce it. For a new component, describe the job it does on a real screen and link any prior art.
